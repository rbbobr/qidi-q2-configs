# Обновление custom до QIDI Q2 01.01.03.02

База: `origin/qidi-studio`, коммит `eb638f16a5c55b92788a4a07731ba3976d572607`.
Заводской снимок `default/` не изменён. Целевая прошивка — **01.01.03.02**;
обратная совместимость со старой прошивкой не заявляется.

## Оценка и принятые решения

Custom сохраняет полезную последовательность: очистка сопла, прогрев стола и
камеры, повторный Z-homing, Z-tilt, адаптивная сетка, парковка и окончательный
нагрев сопла. После печати филамент остаётся загруженным. При отмене нет
парковки XY, обрезки или выгрузки в пользовательских макросах.

| Изменение | Решение |
| --- | --- |
| `[box485]`, `[box2base]`, `INIT_RFID_READ`, `T0…T15` и новые вспомогательные макросы | Перенесены из заводского снимка. Параметры Box сохранены без изменений. |
| Задержка в `TRY_INTO_EXTRUDER` | `G1 P1000` заменена на `G4 P1000`. |
| Завершение `M604 T=2` | После продувки выключаются сопло и вентилятор. Ручные процедуры явно задают G90/M83. |
| `G28 O` / `LAZY_HOME` | Перенесены с исправлениями: нет вызова базового G28 при пустом наборе; поддержаны все сочетания XYZ. |
| Отдельный `G28 Z` | При найденных XY сохраняет позицию XY для калибровки. Иначе сначала находит недостающие XY и переходит в центр. |
| Начальный homing с неизвестным Z | Сохранён заводской приём: условная координата Z и начальный подъём 5 мм. Это исключение относится только к homing, не к `SAFE_Z_LIFT`. Требует аппаратной проверки. |
| `SAFE_Z_LIFT` | Использует физическую позицию и меньший из аппаратного и пользовательского пределов. По уточнению владельца оба предела Z установлены в 256 мм. Относительный ход учитывает остаток хода, не опускает Z и сохраняет режим координат. Неизвестный Z не перемещает. |
| Завершение/отмена | Нагрев отключается до движений. Холодный ретракт пропускается; подъём отделён от экструзии. Конечные движения вычисляются отдельным макросом после M400. Если для подъёма нет хотя бы 1 мм, завершающие wipe/парковка XY пропускаются. |
| Таймер вентилятора | Отменяется в начале новой печати. Обработчик не выключает вентилятор при printing/paused. |
| Возврат после очистки | После подъёма до Z=30 перемещение к центру выполняется одной командой G0 по X/Y одновременно, по уточнению владельца. |
| `M106 P4` | Исправлен регистр имени выхода: `polar_cooler`. |
| Адаптивная сетка | Одно определение в `Adaptive_Meshing.cfg`, минимум 4×4; margin=10, fuzz=2. |
| Повторные секции | Идентичные `gcode_arcs` и `exclude_object` оставлены только в printer.cfg; параметры сохранены. |
| Парковка/продувка | Общий расчёт, учёт полного завершающего хода 10 мм, отступ 1 мм от границ печати/оси. Линия перед общим контуром объектов, иначе слева. |
| Ретракт KAMP | Команды G10/G11 — строки. После завершающего хода и подъёма ретракт компенсируется. Режимы координат и экструзии восстанавливаются. |
| Box buffer | Включается после `T[initial_tool]` и перед `LINE_PURGE`; с внешней катушкой вызов ничего не делает. |
| Экономия полной продувки Box | Отключена: сохранённый номер слота и датчик не подтверждают актуальный материал после перезапуска. Полная продувка выполняется при каждом старте с Box. |
| Универсальный `TRY_RESUME_PRINT` | Безусловный вызов из заводского RESUME не перенесён. Box использует TRY_RESUME_PRINT, внешняя катушка — RESUME_PRINT с проверкой филамента. |
| Выключенный Box | Проверки наличия/включения Box используют значения по умолчанию. Ручная загрузка и выгрузка не вызывают E_LOAD/E_UNLOAD, если Box выключен. |

PID, токи двигателей, шаги/rotation_distance, pressure advance, input shaper,
аппаратные пины и пределы X/Y не перенастраивались. По указанию владельца предел Z изменён с 265 на 256 мм, PRINTER_PARAM.max_z_position — с 260 на 256 мм. Автокалибровку из реального
`SAVE_CONFIG` на принтере нужно сохранить при установке.

## Проверка действующей прошивки по SSH/API

На проверенном Q2 `/home/mks` является ссылкой на `/home/qidi`; оба пути
ведут к одному каталогу конфигурации. Используется Jinja2 2.11.3.
Несмотря на вызовы в заводских макросах, команды SAVE_LAST_FILE, CLEAR_LAST_FILE,
E_LOAD, E_UNLOAD, M300 и _KM_IDLE_TIMEOUT в работающей прошивке не зарегистрированы.
Поэтому optional-вызовы SAVE_LAST_FILE/CLEAR_LAST_FILE выполняются только при
наличии команды; иначе выводится сообщение. Восстановление после потери питания
этими устаревшими callback-командами не заявляется.
Для звука используется существующий BEEP; idle_timeout выключает двигатели M84,
если отсутствует _KM_IDLE_TIMEOUT. M603/M604 T=0 для включённого Box со старым API
останавливаются с сообщением использовать QIDI Studio ещё до движений/нагрева.
M604 T=2 и процедуры внешней катушки сохраняются.

## Изменившееся поведение

- `PRINT_START BED=... HOTEND=... CHAMBER=... EXTRUDER=...` сохраняет интерфейс.
- `G28` без O всегда выполняет запрошенный homing; `G28 O` пропускает найденные оси.
  Для Z могут дополнительно потребоваться неизвестные XY. `LAZY_HOME` по умолчанию
  использует `LAZY=1 AXES=XYZ`; недопустимое AXES вызывает ошибку.
- `LINE_PURGE` и `SMART_PARK` требуют полигонов объектов. В QIDI Studio необходимо
  включить маркировку объектов; в итоговом G-code `EXCLUDE_OBJECT_DEFINE` должен
  находиться **до PRINT_START**. Без метаданных подготовка останавливается,
  поскольку невозможно подтвердить, что линия не попадёт под деталь.
- Если с учётом purge_margin=20 и длины линии нет места перед объектами или слева,
  подготовка останавливается. Передвиньте объекты или уменьшите настройки продувки;
  автоматического переноса линии поверх детали нет. Учитывайте также юбку,
  brim и башню очистки: полигоны объектов могут их не описывать.
- Парковка не опускает уже поднятую голову. Перед продувкой сопло опускается
  до purge_height. Длина линии и расход сохранены: 30 мм филамента, flow_rate=12.
- Завершающий подъём теперь целиком принадлежит `PRINT_END`; старую команду
  `SAFE_Z_LIFT` из конечного G-code слайсера нужно убрать.
- Voron_Purge остаётся отключённым. В нём исправлены только кавычки G10/G11;
  проверка ограничений траектории относится к LINE_PURGE, не к логотипу Voron.

QIDI указывает для 01.01.03.02 использование актуального QIDI Studio для настроек
филамента Box; управление этими настройками через Fluidd не поддерживается:
[примечания производителя](https://www.qidimaker.com/en/downloads/firmware/Q2).
Это не равнозначно запрету обычной отмены печати через Fluidd.

## Проверки в репозитории

При подготовке изменений все 16 групп тестов прошли, включая 128 сочетаний
homing и 240 вариантов подъёма Z. `git diff --check` прошёл; diff каталога
`default/` относительно eb638f1 пуст. Выполненная часть аппаратной приёмки описана ниже.

```sh
python -m pip install -r tests/requirements.txt
python -m unittest discover -s tests -v
git diff --check
git diff eb638f1 -- default
```

Последняя команда должна дать пустой diff. Тесты проверяют:

- подключение доступных файлов, уникальность секций и компиляцию активных Jinja;
- 128 сочетаний запрошенных/найденных осей и флага O, Z-only в точке калибровки;
- 240 сочетаний высоты, смещения, режима координат, homing и подъёма;
- линии у краёв, отсутствие места/объектов, холодное сопло, координатные смещения;
- холодную/горячую отмену, неизвестные оси, завершение у верхнего предела;
- отмену таймера при следующем старте и защиту таймера при паузе/печати;
- консервативную продувку при одинаковом/другом сохранённом слоте, оба режима подачи;
- диспетчер RESUME, ручную загрузку, порядок команд слайсера и границы сетки.

Используется Jinja2 3.1.6 с разделителями Klipper. Упрощённый исполнитель моделирует
режимы координат, движения, dispatch homing и состояние макросов. Он **не запускает
QIDI Klipper** и не моделирует MCU, датчики, нагрузку на механику, трансформацию
bed mesh, асинхронные операции Box или внутренние обработчики отмены/возобновления.
Команды нагрева в нём записываются, а тепловая динамика не моделируется.

## Установка

1. Убедиться, что принтер простаивает и установлена 01.01.03.02. Сохранить полный
   каталог `~/printer_data/config`, `saved_variables.cfg`, действующие шаблоны
   слайсера и `klippy.log` вне изменяемых файлов. Например, на принтере:

   ```sh
   cp -a ~/printer_data/config ~/printer_data/config-before-q2-custom-$(date +%Y%m%d-%H%M%S)
   ```

2. Проверить полный граф подключений действующей конфигурации. В этом репозитории
   отсутствуют `MCU_ID.cfg`, `timelapse.cfg`, `box.cfg` и исходники Box.
   В штатных подключениях не должно быть повторных T0…T15, G28, `_KAMP_Settings`,
   `BED_MESH_CALIBRATE`, `[box485]` или `[box2base]`. Старый штатный KAMP не должен
   одновременно подключаться с `KAMP_custom`.

3. Проверить наличие модулей `box485`, `box2base` и команд прошивки, включая
   `INIT_RFID_READ`, `T_MANAGER`, `TRY_RESUME_PRINT`, `BOX_PRINT_START`,
   `BUFFER_MONITORING`, `DISABLE_BOX_HEATER`, `CLEAR_TOOLCHANGE_STATE`,
   `CLEAR_OOZE`, `CLEAR_FLUSH`,
   `SET_PRINT_MAIN_STATUS`, `SET_PRINT_SUB_STATUS` и обработчики, переименовываемые
   в `BASE_CANCEL_PRINT`/`BASE_RESUME`. Отсутствующие vendor-команды не заменять
   пустыми заглушками. Если модуль/команда отсутствует, остановить установку и
   сверить состав прошивки, не запускать печать.

4. Скопировать файлы по соответствию:

   | В репозитории | На принтере относительно `~/printer_data/config/` |
   | --- | --- |
   | `custom/configs/gcode_macro.cfg` | `klipper-macros-qd/gcode_macro.cfg` |
   | `custom/configs/custom_macro.cfg` | `klipper-macros-qd/custom_macro.cfg` |
   | Все файлы `custom/KAMP/`, включая новый `Purge_Path.cfg` | `KAMP_custom/` |

   В действующий `printer.cfg` перенести секции `[box485]`/`[box2base]` из custom
   и подключения `klipper-macros-qd/gcode_macro.cfg`, `KAMP_custom/KAMP_Settings.cfg`.
   Сохранить его реальные MCU ID, калибровки, SAVE_CONFIG и аппаратные изменения.
   Не заменять полный действующий `printer.cfg` снимком без сравнения.

5. В копии пользовательского профиля OrcaSlicer заменить стартовый и конечный G-code содержимым
   `custom/slicer/start.cfg` и `custom/slicer/end.cfg`. Остальные шаблоны слайсера
   не изменялись. Проверить итоговый нарезанный G-code: определения объектов до
   PRINT_START; выбор инструмента, ENABLE_BOX_BUFFER, затем LINE_PURGE.
6. Выполнить RESTART, проверить состояние ready, журнал и отсутствие ошибок
   регистрации команд/подключений. Не запускать файл печати при ошибке загрузки.

Проводить на свободном столе, наблюдая за первой проверкой каждого движения.

1. Проверить полный homing, отдельные X/Y/Z и G28 O. Повторный G28 O после
   полного homing не должен двигать оси; G28 Z при известных XY сохраняет точку XY.
2. Проверить SAFE_Z_LIFT при известном Z, рядом с верхним пределом и после
   отключения моторов. Неизвестный Z должен пропускаться, а подъём — не опускать Z.
3. Проверить маленькую печать в центре и рядом с краями, парковку и продувку;
   отдельно проверить отсутствие места и отсутствие метаданных объектов.
4. С внешней катушкой: холодная отмена, отмена во время нагрева, пауза/возобновление
   с филаментом и без него, нормальное завершение.
5. С Box: тот же слот, другой слот, старт после перезапуска, окончание филамента,
   пауза/возобновление, ручная загрузка M604 T=2. Проверить работу буфера.
6. Запустить следующую печать до истечения 180 секунд после предыдущей;
   старый таймер не должен выключить вентилятор новой печати.
7. Воспроизвести отмену после начала нагрева через Fluidd и сохранить klippy.log.
   Двойная обрезка не объявляется исправленной: её источник может находиться
   внутри QIDI Box/BASE_CANCEL_PRINT, которых нет в репозитории.

## Откат

Остановить печать, восстановить изменённые файлы конфигурации и шаблоны слайсера
из **одной** резервной копии, включая исходные подключения в printer.cfg.
Сохранить появившиеся журналы отдельно. Выполнить RESTART и проверить загрузку.
Это откат пользовательского профиля, а не понижение версии прошивки.
Новые неподключённые файлы можно оставить до завершения диагностики.

## Причина отсутствия материала 1B в Fluidd

Диагностика на установленной панели **v1.30.5-ab46ef6**, bundle
`assets/index-DlFvHGAh.js`: виджет показывает `?` для 1B, хотя
`box_extras.loaded_slot=slot1`, датчик головки обнаруживает филамент и
`box_stepper slot1.runout_button=0` подтверждает наличие катушки.

Панель читает `save_variables.variables.filament_slot1` через `parseInt` и ищет
материал в старом каталоге `fila<число>`. В новой прошивке значение — строка
`QFN05`, поэтому получается `NaN` и несуществующий ключ `filaNaN`.
Цвет `color_slot1=['060606']` тоже ошибочно трактуется как индекс палитры 60606,
вместо HEX-цвета. Новые `box_extras.boxes[0].filament_info[1]` уже содержат
правильные PA6-CF и `#060606`, но bundle не читает `filament_info` вообще.

Надпись PA6-CF в карточке Rack относится к отдельно сохранённому профилю внешней
катушки (`filament_slot16=25`), а не к подтверждению её физической загрузки.
Причина — несовместимость старого виджета с новым форматом прошивки, а не KAMP,
обрыв связи Box или отсутствие материала. Пробная загрузка из 1B подтверждена
датчиком и владельцем.

Официальный путь настройки Box в этой версии — QIDI Studio:
[QIDI, changelog 01.01.03.02](https://www.qidimaker.com/en/downloads/firmware/Q2).
Возврат переменных к старым числам ради отображения нарушит новый формат данных.
Существует отдельный общественный
[патч веб-панели](https://github.com/Greg-LFT/Qidi-Q2-Fluidd-widget-box-repair),
который заявляет поддержку нового API. Он не устанавливался и не проверялся
в этой работе. Для отображения установлен отдельный минимальный адаптер, описанный ниже.


## Исправление отображения Fluidd — установлено и проверено

На основном адресе `http://192.168.1.19/` после обычного обновления страницы
проверены подпись **1B → PA6-CF** и цвет катушки **#060606** в DOM виджета.
Первый вариант адаптера уже исправлял данные, но основной браузер сохранял старый
JS в кеше; проверка через штатный порт 10088 подтвердила эту отдельную причину.

`tools/fluidd_material_display.js` дополняет только отображаемые карточки
данными `box_extras.boxes[].filament_info`. Пустые слоты и Rack сохраняют прежнее
поведение. Адаптер не записывает переменные, не меняет настройки Box и не
посылает команды загрузки/выгрузки. Поля редактирования материала и автоматическая
подмена катушек не переводились на новый API и этой проверкой не подтверждены.
Полное управление материалами по-прежнему следует выполнять через QIDI Studio.

`tools/patch_fluidd_display.py` проверяет точное совпадение участка поддерживаемой
сборки, создаёт версионированные копии изменённого модуля и зависимых JS-файлов,
обновляет ссылки в `index.html` и записи кеша `sw.js`. Обратные зависимости
обновляются вместе, чтобы циклический импорт не загрузил вторую копию приложения.
На принтере созданы 16 JS-файлов и обновлены два входных файла; контрольные суммы
всех 18 файлов проверены. Исходные зависимые модули сохраняются.

Для установки на такой же исходной сборке скопировать оба файла из `tools/`
в одну временную папку принтера и выполнить:

```sh
python3 patch_fluidd_display.py --root /home/qidi/fluidd
sudo python3 patch_fluidd_display.py --root /home/qidi/fluidd --apply
```

Первая команда только проверяет и показывает изменения. Установка сохраняет
резервную копию входных файлов с манифестом в `codex-display-backup-<UTC>/`.
Повторную установку поверх версионированного адаптера скрипт отклоняет: сначала
нужно восстановить соответствующую резервную копию. Обновление штатного Fluidd
может заменить исправление; совпадение версии нужно проверять заново.

На данном принтере полное возвращение панели к состоянию до всех попыток патча:

```sh
sudo cp -a /home/qidi/fluidd/codex-display-backup-20261108T201538Z/assets/index-DlFvHGAh.js /home/qidi/fluidd/assets/index-DlFvHGAh.js
sudo cp -a /home/qidi/fluidd/codex-display-backup-20261108T201538Z/sw.js /home/qidi/fluidd/sw.js
sudo cp -a /home/qidi/fluidd/codex-display-backup-20261108T203804Z/index.html /home/qidi/fluidd/index.html
```

После установки/отката обновить страницу. RESTART Klipper не нужен.
Новые неподключённые JS-файлы можно оставить. Конфигурации принтера этим откатом
не затрагиваются. Проверки: Node-тесты данных и неизменности входных объектов,
тест циклических импортов и манифеста кеша; всего 17 Python-тестов вместе
с ранее добавленными тестами конфигураций прошли.


## Плавная подготовка и SMART_PARK

По запросу владельца добавлен временный режим `_PREP_MOTION`:

- Подготовительные переезды ограничены 150 мм/с, ускорение — 2000 мм/с²,
  `square_corner_velocity` — 5 мм/с. Если исходный предел ниже, он сохраняется.
- По уточнению владельца рабочие движения очистителя сохраняют прежние
  скорости и ускорения (CLEAR_NOZZLE: 5000 мм/с²). Ограничения подготовки
  временно снимаются только для очистки/сброса продувки и возвращаются перед
  переездом. Подход к очистителю и возврат к центру остаются плавными.
  Возврат — единое движение XY, 150 мм/с вместо прежних 300 мм/с.
  Геометрия очистки и величины подачи/ретракта не менялись.
- Вложенные M204 не повышают ускорение выше лимита подготовки. После
  BOX_PRINT_START ограничения применяются заново.
- SMART_PARK и переезд после продувки запрашивают не более 150 мм/с.
  Отдельный вызов SMART_PARK/LINE_PURGE сохраняет и восстанавливает ограничения;
  внутри PRINT_START он использует уже активный режим без перезаписи сохранённых значений.
- Sensorless homing сохраняет прежнюю последовательность, скорости и M204 S10000;
  после homing снова включаются ограничения подготовки.
- Перед окончанием PRINT_START, после отдельной продувки/парковки и при
  штатном завершении CANCEL_PRINT/PRINT_END явно восстанавливаются скорость,
  ускорение, square_corner_velocity и minimum_cruise_ratio. Жёсткое M204 S10000
  в конце PRINT_START заменено восстановлением исходных значений.
- При ошибке подготовки до её завершения мягкие ограничения остаются активными
  до отмены или `_PREP_MOTION_END`; это не команда движения.

Проверка: все 20 Python-тестов прошли, включая вложенные вызовы, сохранение
более низких лимитов, отмену, исключение для homing и скорости KAMP.
Три файла установлены на принтер, RESTART завершился состоянием ready.
Без движений и нагрева проверены фактические лимиты 150/2000/5, защита от
M204 S10000, вложенное сохранение, исключение homing и возврат 600/10000/8
с исходным minimum_cruise_ratio=0.5. При подготовке аппаратной проверки кеша сетки владелец подтвердил, что
переезды стали плавнее. Последующее исключение для штатной очистки проверено
автоматическими тестами; повторная оценка её качества отдельно не проводилась.

Резервная копия трёх предыдущих файлов на принтере:
`config/codex-backup-20261108T191005Z/before-smooth-prep-20261108T205037Z/`.
Для отката восстановить из неё `klipper-macros-qd/gcode_macro.cfg`,
`KAMP_custom/Smart_Park.cfg`, `KAMP_custom/Line_Purge.cfg` вместе и выполнить
RESTART на простаивающем принтере. Изменения Fluidd и Z=256 этим не отменяются.


## Повторное использование сетки с контрольными измерениями

Режим реализован в `custom/KAMP/Mesh_Reuse.cfg`, подключён через KAMP_Settings.
PRINT_START после прогрева, точного G28 Z и Z_TILT_ADJUST вызывает
`QIDI_MESH_PREPARE`. При первом запуске выполняется обычная адаптивная сетка
(минимум 4×4) и ещё пять контрольных измерений: четыре угла фактически
измеренной области и её центр. Каждое контрольное измерение — два касания,
как в настройках probe_air. Первый запуск поэтому дольше обычной калибровки.

Перед повторным использованием проверяются:

- Наличие кеша и неизменность сохранённых точек и границ профиля `q2_cached`.
- Вхождение полигонов новых объектов и принятого KAMP-запаса 10 мм в старую
  область; запас у границ ограничен штатными mesh_min/mesh_max. Сами объекты
  должны помещаться внутри фактически измеренной области. Имя файла/модели
  не используется как доказательство совпадения геометрии.
- Совпадение целевых температур стола и камеры (допуск 0,1 °C); фактические
  температуры относительно исходного измерения: стол ±2 °C, камера ±3 °C,
  сопло ±5 °C. Для включённых нагревателей проверяется достижение целевых
  температур стола/камеры. Температуры проверяются снова после пяти точек.
- Возраст кеша не более четырёх часов; отсчёт не продлевается после reuse.
- XYZ найдены, Z_TILT_ADJUST выполнен, G-code offsets XYZ нулевые,
  сопло очищено и остыло до температуры измерения (в старте обычно 140 °C).

Если условия подходят, сетка отключается, заново измеряются те же пять точек.
Максимальное **абсолютное** отклонение каждой от исходного значения должно быть
не более **0,03 мм**. Общее смещение всех точек не вычитается: оно тоже вызывает
перекалибровку. При совпадении загружается прежний профиль; при несовпадении
строится новая сетка с новым набором контрольных значений. Исходные контрольные
значения не заменяются после успешной проверки, чтобы дрейф не накапливался.

Сетка измеряется и проверяется с выключенной mesh-компенсацией. Перед каждым
переездом обеспечивается Z≥5 мм с учётом предела Z=256; скорость переезда
100 мм/с, действует режим плавной подготовки. Ошибка датчика/неполное измерение
останавливает подготовку, кеш остаётся недействительным. Это отличается от
успешного измерения с несовпавшей высотой, при котором выполняется новая сетка.

Кеш живёт только в текущем сеансе Klipper: после RESTART/выключения первая печать
обязательно строит новую сетку. Автоматического SAVE_CONFIG или записи данных
контрольных точек во flash нет. Отключение моторов после печати не означает
безусловного доверия кешу — следующий старт заново делает homing, tilt и контроль.

Команды:

```gcode
QIDI_MESH_INVALIDATE
```

Выполнять после снятия/переворота/замены пластины, изменения слоя клея или работ
со столом/соплом. Команда не двигает принтер и заставляет следующий старт строить
новую сетку. Пять точек не обнаруживают произвольные локальные деформации между
ними и не определяют автоматически смену пластины. Полигоны объектов и запас
должны покрывать весь первый слой; для brim/skirts шире запаса необходимы
соответствующие метаданные/увеличение запаса или принудительная новая сетка.

```gcode
QIDI_MESH_PREPARE FORCE=1
```

Принудительная новая сетка после обычной подготовки и обнуления offsets.
Для PRINT_START также доступен параметр `MESH_FORCE=1`; старые параметры
BED/HOTEND/CHAMBER/EXTRUDER сохранены. При необходимости отключить reuse в текущем
сеансе: `SET_GCODE_VARIABLE MACRO=_QIDI_MESH_CACHE VARIABLE=enabled VALUE=0`.
Сообщения консоли указывают причину новой калибровки или максимальное отклонение
при успешном reuse. Состояние/счётчики доступны в `_QIDI_MESH_CACHE`.

Резервная копия перед установкой:
`config/codex-backup-20261108T191005Z/before-mesh-reuse-20261108T210626Z/`.
Откат: восстановить `KAMP_custom/KAMP_Settings.cfg` и
`klipper-macros-qd/gcode_macro.cfg` из этой копии, выполнить RESTART при простое.
Неподключённый Mesh_Reuse.cfg можно оставить. Плавная подготовка, Fluidd и
предел Z=256 сохраняются.
